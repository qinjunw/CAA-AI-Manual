# 精确成员引用：跨 Framework 与配对模型检查

## 结论

本轮保留 `Class::Member(...)` 的精确锚点定位修复。此前已存在的成员加上索引参数列表后无法直接定位；修复后，107 个留出 Framework 的 811 个成员在三种表示下全部定位到预期身份，未新增错误唯一选择。

**没有证据表明本轮提高了模型回答正确率或降低了模型查询成本。** 两个模型、8 道声明读取题、两次重复构成的 32 对测试，两版均为 32/32 严格通过。轨迹显示模型均未调用新增参数定位语法；总 token 虽下降 1.40%，不能归因于修复。

检查日期：2026-09-14。依据为 [预注册检查](reference-transfer-plan.md)、[一手资料调研](retrieval-methods-research.md) 和 [去除正文的测量数据](reference-transfer-metrics.json)。本轮基线是上一轮已改进的查询实现，不是原始 HTML 手册；历史结果不能与本轮增量相加。

## 实现和范围

[查询实现](../tools/caa_manual_query.py) 将限定名拆为类、方法名和可选索引参数锚点，再精确匹配索引记录。它规范化空白、HTML 实体和全宽字符，保留类型名大小写、单词边界、`const`、指针和引用；参数中的命名空间与模板逗号不会被误当成类 / 方法分界。

匹配失败时提示改查 `Class::Member`，从候选成员 ID 继续；重复锚点保持歧义。派生类存在同名声明时，不因请求的锚点未命中而继续选取基类重载。索引参数可能省略原文中的限定符，故定位表达式不能代替完整 C++ 声明，也不实现默认实参或隐式转换。

本轮未修改任务词表、排序、MCP 工具定义、系统提示、旧题答案或公开数据库。README 与调用指南在模型测量结束后补充语法说明，未加入该轮模型上下文。源码库和父级 Wiki 没有因本轮工作被改写。

开发集在候选版的五类检查均为 64/64；基线的三种新增表示均为 0/64，名称入口与反例均为 64/64。三种表示来自同一成员，不是 2,433 道独立知识问答题。0/811 也不表示基线无法查到这些 API：原名称、成员 ID 和 URI 入口仍可使用。

两条名称入口异常均来自 CATTTRSInterfaces：`CATMathPrismaticRGE` 和 `CATMathCylindricalRGE` 同时含 `GetTTRSClass` / `GetTTRSclass`。采样预期按大小写区分名称，旧、新查询均按既有不区分大小写规则返回两个候选。因此这是已存在的歧义与采样预期差异，不是本轮退化；未在留出检查后调整规则或重算为通过。

源页抽查按另一个固定种子选择 32 个留出成员，覆盖 25 个 Framework。限定参数引用与成员 ID 入口返回的源 URI、锚点、首段非空正文及分页元数据全部一致。抽查每次读取 1,000 字符，只证明这段输出一致，未逐页验收全部 CAADoc 内容。

采样仅覆盖普通标识符方法及 `Name(...)` 形式锚点。构造 / 析构、运算符、Automation、任意命名空间限定的类名和完整 C++ 类型语法未由本轮留出结果验证。声明按 Framework 分组，但共享的继承目录仍是同一个本机来源，不称为所有依赖均隔离的盲测。

## 模型配对结果

[题库](../tests/fixtures/reference_transfer_agent.json) 使用 8 个不同留出 Framework 的声明，要求从本机原文读取返回类型、完整参数类型和证据 URI。成员选择依据固定哈希，不按候选成功与否筛选；先核对题目预期，再发起模型调用。预期答案和实现快照不进入提示。

[配对脚本](../tools/benchmark_agent_transfer.py) 在同一模型、题面、重复编号下轮换旧 / 新顺序；两版使用相同工具定义、JSON 模式、温度 0、关闭思考设置、最多 6 轮及每轮 1,200 输出 token。每个模型每版运行 16 例，两次均通过的题目均为 8/8。共 64 次运行，累计 505,138 token，无超时、预算中止或失败样本被排除。

| 模型 | 严格通过：旧 → 新 | 总 token：旧 → 新 | 工具调用：旧 → 新 |
| --- | ---: | ---: | ---: |
| deepseek-flash | 16/16 → 16/16 | 139,079 → 139,160 | 49 → 48 |
| deepseek-v4-pro | 16/16 → 16/16 | 115,275 → 111,624 | 35 → 34 |
| 合计 | 32/32 → 32/32 | 254,354 → 250,784 | 84 → 82 |

配对胜负为：均通过 32、仅新版通过 0、仅旧版通过 0、均失败 0。全样本和“两版均通过”的成本口径相同；16 个“任务 × 模型”组的两次重复，两版均全部通过。严格通过要求完整结束、严格 JSON、规定字段及原文轨迹检查通过；引用检查到页面级，不等于片段语义或 C++ 可编译性证明。

调用轨迹中，64 次运行都使用不带参数的限定名、成员 ID 或源 URI；**直接使用新增参数定位语法为 0 次**。因此不能把 token 减少 1.40% 或工具调用减少 2 次解释为新语法的收益。Flash 的 token 还小幅上升；温度 0 也未让所有调用轨迹相同。这里仅记录观测值，不作显著性判断或通用模型外推。

这组题已经触及正确率上限，且两模型来自同一提供商。它支持“这些声明读取任务未退化”，不支持“通用大模型已更会选择和调用 CAA API”。本轮未执行 CAA 编译、对象构造或 CATIA 运行。

## 下一轮候选与停止条件

本次资料调研将工具可用性、分组评测和重复稳定度作为不同问题处理；方法依据见 [调研来源及推论](retrieval-methods-research.md)。下一轮建议按以下顺序独立检验，不继续修改本轮题面追分：

1. **能力能否被模型发现。** 单独对照工具描述是否明确披露参数定位入口，使用新的声明组和正常任务表述；记录自然采用率与额外调用数，不能通过强制路径后宣称自然查询效率提高。
2. **区分索引与正文证据。** 检验统一的证据状态和规范引用 URI 是否减少未读引用、部分正文被当成完整契约的错误，同时记录新增响应 token。仅获得链接不能算读取证据。
3. **补足任务难度和失败边界。** 新留出覆盖“用途 → 候选 → 输入类型 → 约束”的多步问题、错误前提、重载歧义、缺失源页与版本不一致；验收合法结果，不只验收预设工具路线。有额外模型接入后再检查跨提供商迁移。

每次只冻结一个候选进入新留出，先报告配对旧错新对 / 旧对新错、重复全通过和错误类型，再看 token。若新增元数据或描述没有可重复收益，停止添加字段与题目专用提示。当前证据不足以支持新增向量库、训练重排器或继续扩大任务同义词表。
