# API 查询工具下一轮迭代：方法与反过拟合边界

## 结论与检查范围

建议本轮只检验 `Class::Member(...)` 精确锚点定位：当前实现对带括号写法没有独立解析路径，可用跨 Framework 的符号身份对照检验，不必先增加有歧义的知识问答题。响应中区分“索引定位”和“本次返回的原文片段”仍是后续候选，但本轮不与前者混合。资料本身不能决定两项在本仓库的收益大小；此次优先级依据是本地可复现问题与可验证范围。

这是待验证方案，不是效果结论。检查日期为 2026-09-14；本地依据是 [上一轮稳定性报告](agent-stability.md)、[查询实现](../tools/caa_manual_query.py) 和 [调用端指引](../docs/AGENT_QUERY_GUIDE.md)。检查时查询文件 SHA-256 为 `2b3a78727cd87fe43e9ae71731ffb2e1e810c490bf0fc8c6465070a2006534af`，分支为 `codex/improve-agent-retrieval`；该指纹用于区分随后并行实施的变化。

上一轮已知失败集加入指引后的 28/32 是回归结果，不能继续视为未知题上的泛化证据。旧留出题已参与失败分析，本轮应全部转为回归集。报告还记录了“实际重载合法，但题面未约束到预设输入类型”的评分问题；新题需先写清持有对象与参数类型，不能用事后修改标准提高旧成绩。

## 两个候选改动的边界

### A：证据状态和规范引用

检查时，`_page()` 返回 `source_uri` / `source_available`，`read_source()` 返回原文、锚点和字符分页；这些字段能表明来源及读取范围，但尚无直接表示“本次结果中含有正文”的统一字段。`source_available` 只是文件存在性检查，不能用于证明模型读过正文。[本地实现](../tools/caa_manual_query.py)

最小方案是在现有响应中增加可机器检查的状态，并明确其仅描述本次响应。例如，索引结果使用 `evidence_kind=index_locator`；成功返回非空原文的读取结果使用 `evidence_kind=source_excerpt`，同时返回规范的 `citation_uri`。字段名由实现确定；不引入新工具、不自动展开所有候选正文，不把 `source_excerpt` 命名为“已证明正确”。

引用 URI 应由已经解析成功的页面和锚点生成，而不是回显模型输入。片段编码只处理 URI 表示，不更改锚点语义。分页仍使用现有 `offset`、`next_offset` 和 `truncated`：返回一段正文不代表整个声明、全部约束或整页都已读取。锚点缺失、读取失败或超出内容范围的空结果不能被标记成成功正文证据。

调用端可记录每次实际返回的 URI、锚点与范围，并检查模型引用是否包含在轨迹中。这只能验证引用来源和读取范围，不能单独证明所引用片段支持某项结论；语义支持仍需字段契约和人工抽检。

反证条件：新字段使模型把部分正文当成完整契约；引用错误未减少；出现漏读约束的增加；或者响应字节数上升却没有稳定度或调用次数收益。若发生这些情况，保留必要的接口事实说明，不继续添加同义状态字段或面向特定试题的提醒。

### B：限定成员签名的精确定位

检查时，`_qualified_members()` 将 `::` 后的全部字符串当作成员名匹配，因此带括号的写法未形成独立签名解析路径；已有成员 ID 和 URI 锚点仍可精确读取。[本地实现](../tools/caa_manual_query.py)

可接受的小修补是：将“类名、成员名、可选的原样签名/锚点”分开处理；优先匹配索引已有身份，返回选中的成员 ID 和匹配方式。空白、HTML 实体、URI 编码或明确界定的全宽标点可做表示归一，但不得把模糊候选升级为身份相等。索引签名可能省略 `const` 等声明信息，不能把它称为完整 C++ 类型系统；精确定位之后仍需读取完整原文。

特别应测试参数中含 `::`、模板逗号、指针和引用的输入。实现若不支持某种语法，应返回明确候选或未支持状态，不使用简单字符串切分误选重载。不要通过删除所有 `const`、`*`、`&` 或参数来制造“唯一匹配”；不能唯一确认时保留歧义。

反证条件：不同重载被合并、大小写或类型差异被静默抹去、父类重载集被不正确合并，或者新增语法没有减少一次实际定位步骤。语法兼容测试通过可以说明修复生效，但不能单独证明模型总体成功率提高。

## 最小可复核实验

以下为本仓库建议，需在付费调用前冻结，并记录任何偏离。

1. **固定对照。** 保存当前查询代码、工具描述、调用端提示、题库、原文版本和评分器的指纹。对照与候选仅切换本轮改动；模型、预算、JSON 模式和停止条件相同。
2. **开发与留出按组隔离。** 新题先按 Framework 分层，再按类/声明家族分组；同一声明的继承别名、相邻重载和改写题不得跨组。共享基类不可能完全隔离时披露重叠，不称为完全跨 Framework 盲测。固定留出组在最终实现确定后只评一次；检查结果后不再用该组调参。
3. **验收事实，不固定路径。** 题面明确已持有输入类型、允许或禁止的转换、需要哪一级证据。允许读取同一官方声明的不同合法路径。只有任务本身要求分页或错误恢复时，才把特定流程纳入验收。
4. **分离两项改动。** 本轮仅 B，对照为未增加签名/锚点解析的版本，不调整任务词表或模型提示。离线先检查同一符号在 `member_id`、URI 锚点、限定签名三种入口下是否解析到同一身份，并检查近似却不同的类型不被接受。以后若同时评估 A 和 B，应先在开发集做原版、仅 A、仅 B、A+B 的消融，再冻结一个候选做留出对照；不必为此长期增加公开配置开关。
5. **配对和重复。** 同一模型、同一题面、同一重复编号构成一对；交错执行两版本并预先固定顺序，减轻服务端随时间变化的影响。至少两次重复，报告旧错新对、旧对新错、均对、均错，以及每个 API 家族的两次均通过率。两次只是最低观察量，不是稳定度的充分证明。
6. **同时看质量和成本。** 主指标是完整结束且规定字段、读取轨迹、引用均通过；次指标为额外未读引用、歧义误选、工具调用数、输入/输出 token 与截断。成本同时报告全样本和两版本都通过的配对样本，防止“提前失败，所以更省 token”被记作效率收益。
7. **保留失败和不确定性。** 不排除工具错误、超时和预算耗尽样本；分别说明基础设施失败与任务失败。组数少时只报告观测差异，不作总体显著性或通用模型泛化承诺。若计算区间，应按家族保留相关性地重采样，而非独立重采样每个改写和重复。

本轮可采纳条件：离线契约测试不回退；新留出中没有新增误选身份或把空结果当证据；至少一个预先指定的目标指标改善，且严格成功数不下降。即使满足这些条件，也只表述为“此留出集合上的观测结果”。若没有改善，应保留诊断记录、停止追加提示词补丁，不继续在同一留出集上追分。

本报告未调用付费模型、读取凭据或改变原文数据库。它不建议新增向量库、训练重排器或扩大同义词表：当前可复现问题尚不足以证明这些更大改动能改善身份匹配和证据引用。
