## DeepSeek 智能体对照

端点依据 [DeepSeek 官方调用说明](https://api-docs.deepseek.com/)：`https://api.deepseek.com/chat/completions`。请求模型名 `deepseek-v4-flash`，成功完成的响应实际返回 `model: deepseek-flash`；因此本报告不声称锁定了某个具体发布版本。temperature 为 0，关闭 thinking，每题最多 6 轮，每轮最多 1,600 输出 token。

四道任务分别核查 GetAllCells、曲面外插约束与 Append 类型、C++ 尖括号 include、SetBorderMode 的参数与默认值。每题重复两次，每个工具方案 8 个样本。第一轮轮换方案顺序；第二轮只复测补充了调用提示与证据范围说明的当前手册，未重新跑两个基线。

原文方案提供文件名搜索、范围内原文搜索、带字符分页的原始 HTML/C++ 读取；不使用 SQLite、别名、成员锚点提取或私有 FTS。它只是一个明确实现的原始文档访问基线，不代表浏览器、IDE 搜索或所有原始 API 手册工作流。

| 方案 | 在轮数内输出最终回答 | 工具调用总数 | API 累计 total_tokens | 总用时 |
| --- | ---: | ---: | ---: | ---: |
| 原始文档工具 | 6/8 | 35 | 147,927 | 41.465 s |
| 旧版手册 | 7/8 | 45 | 136,233 | 53.938 s |
| 首轮修复版 | 8/8 | 43 | 168,685 | 51.364 s |
| 补充证据范围及调用提示后 | 8/8 | 30 | 114,571 | 42.738 s |

最后一组相对旧版：工具调用减少 33.3%，累计 token 减少 15.9%，用时减少 20.8%。相对原文方案：累计 token 减少 22.5%，但总用时增加 3.1%。四组累计使用 567,416 个 API token，包含服务端报告的缓存命中输入；token 数不等于实际计费金额。

**输出最终回答不是正确率。** 原文方案的 GetAllCells 两次到达轮数上限；旧版一次到达上限。对已输出回答的检查发现：

- C++ 题：旧版两次未能给出正确的两条尖括号 include，其中一次断言没有；当前和原文方案均能正确列出。
- Append 题：旧版回答的列表参数漏掉 `const`；当前读取和回答保留了该限定符。
- 首轮修复版的 GetAllCells 答案把继承依据当作推测；加入显式继承链来源后，两次复测均报告了声明类和链条。
- 首轮修复版曾把示例索引为零写成官方没有示例；范围提示加入后，两次复测均保留了“不证明不存在”的限制。
- SetBorderMode 题仍有语义问题：模型会把签名的默认实参与文字中的默认模式直接称为矛盾。`SetBorderMode()` 的省略实参行为与“未调用 setter 时的算子初始状态”应分开核验；本测试未执行 CATIA，不能裁定运行状态。
- GetAllCells 的枚举语义不等于 shell 边界提取；个别回答仍会把面/loop 的示例表述成 shell 边界流程。检索命中和原文保真不能替代拓扑语义审核。

这里没有独立盲评，也没有每项事实全部通过的正确率统计。样本少、题目已知、第二轮针对首轮表现修改提示，且服务端缓存与模型路由不受控；不能把这组百分比推广到其他智能体或 CATIA 开发任务。
