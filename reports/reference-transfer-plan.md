# 精确成员引用迭代：预注册检查

## 假设与变更边界

当前 `Class::Member` 按成员名称定位；追加索引参数列表后，整个 `Member(...)` 被当作名称，导致本来存在的声明无法直接定位。本轮仅验证精确引用语法是否能跨 Framework 工作。

生产变更限于限定成员引用的解析及该语法的错误指引：允许名称后附官方索引锚点参数列表，规范化空白、全宽字符和 HTML 实体。指针、引用、类型名及限定符不能删改；无精确匹配时不猜重载。参数列表是文档定位键，不是 C++ 实参，也不模拟默认实参、隐式转换或完整重载决议。

不新增任务词、不修改检索排序、旧题预期答案或系统提示。索引 / 已读证据结构是另一个候选方案，留待独立验证，避免把多项改变的结果混为一次收益。

## 数据隔离

冻结工具代码、采样脚本和数据库哈希后再修改生产实现。旧题全部作为回归，不作为泛化成绩。

开发范围为此前已接触的 Mathematics、GeometricObjects、GMModelInterfaces、GMOperatorsInterfaces、GSMInterfaces、PartInterfaces、TopologicalOperators、AdvancedTopologicalOpe。其他 CAA-refman Framework 整组留出；不把同一类或同一声明的语法变体分到两组。只抽取名称唯一归属一个 API 节点、名称为普通标识符、具有 `Name(...)` 形式锚点的普通方法，构造 / 析构及运算符不在本轮覆盖内。

每个 Framework 按固定种子 `caa-reference-transfer-v1` 的哈希顺序抽取最多 8 个成员。选择依据只用标识符，不以新实现的成功与否筛选。每个成员测试规范参数引用、含空白 / HTML 实体的引用、全宽标点引用，以及原名称入口和伪造参数类型反例。样本、排除条件和哈希保存在忽略的快照中。

开发集可用于修补实现；实现冻结后才运行跨 Framework 留出检查。留出结果无论好坏都写入报告；若再根据它修改实现，不能再称为同轮独立留出结果。

## 验收条件

- 精确变体定位到目标成员 ID；同名多重载的原入口继续返回完整候选，不任取第一项。
- 参数类型错误、指针 / 引用或限定符变化的反例不得静默选择一个重载。
- 原名称入口的状态及成员身份保持不变；原有测试和 26 条检索回归不退化。
- 开发和留出分别报告样本数、Framework 数、正确定位、错误唯一选择及原入口回归情况，不把语法变体视为独立语义任务。
- 对随机样本的源页读取与成员 ID 入口对比，确认输出内容一致。定位正确不等于模型理解正确，也不等于 C++ 编译或 CATIA 运行通过。

如增加付费模型检查，旧 / 新两组使用相同模型、题面、系统提示、输出限制与工具定义，并轮换执行顺序。不得向模型暴露预期答案或快照源代码；模型测试只作范围有限的补充，不替代上述确定性检查。
