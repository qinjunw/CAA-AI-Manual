# 智能体查询稳定性：2026-09-14

## 结果与范围

工具层 1,000 次并发查询响应一致，数据库未变。两档模型的 96 个重复样本中，81 个通过严格自动验收；对失败集增加调用端查询指引后，同条件的 32 个样本由 17 个通过变为 28 个通过。剩余问题涉及证据引用和输入类型约束，不能据此声称通用模型已能可靠执行任意 CAA API。

本轮只测试索引 / 原文检索、JSON 输出和指定调用字段。没有编译 C++、运行 CATIA 或验证模型中的结果体。MCP 工具保持只读。本机 CAADoc、CATIA-CGM 内容、公开数据库和 Wiki 页面本轮均未修改。

逐样本用量、字段验收和代码指纹见 [测量摘要](agent-stability-metrics.json)。完整回答和原文调用记录留在忽略的 `outputs/`，未公开。

## 冻结输入与验收口径

题库为 `tests/fixtures/agent_stability.json`：12 类问题，每类两种表达。8 类为开发集；4 类为首次验证前未用于修改查询实现的留出集，涉及向量长度、几何点、继承方法及容器类型。预期字段和原文定位在第一次调用模型前确定，只把题面发送给模型。

开发集覆盖零向量、闭合 wire、坐标建点、平面重载、执行及释放规则、Pad 参数、示例分页和不存在的符号。模型看不到预期答案，但这不是随机抽样，也不包含任意未知领域；留出题与开发题在对象类型上仍有关联。

验收分开记录：

- `fields_pass`：规定字段与目标契约匹配。C++ 类型忽略空白，布尔值不接受字符串或数字替代；方法名接受与证据类一致的完整限定名。
- `source_read_pass`：原文读取轨迹包含对应文件和规定片段标记；分页题必须实际依次获取首批 20 项及 offset 20，负例题必须有真实的未命中查询。
- `citation_pass`：声明题的引用页必须实际读取。仅返回路径的索引结果不算读过原文；分页及负例题允许使用实际返回的索引定位。
- `pass`：完整结束、字段、读取轨迹和引用均通过；允许从唯一 JSON 代码块中提取字段。
- `automation_pass`：在 `pass` 基础上要求整个答案是 JSON 对象，不带围栏和附加说明。

开发阶段纠正了验收器对完整限定方法名、唯一 JSON 围栏和索引题引用定位的处理，并新增合成测试；下表对所有阶段统一重新评分，原始轨迹没有覆盖。严格 JSON 与事实字段仍分开计分。完整验证开始后未调整这些验收规则，也未按留出结果修改查询实现。

## 已实施变化

| 复现的问题 | 当前处理 |
| --- | --- |
| MCP 忽略未知参数，将数字字符串和布尔字符串隐式转换 | 查询前校验类型、必填项、枚举、边界及未知字段；错误给出字段位置和重试指引 |
| 无效 JSON-RPC 值归类错误，批处理中一个坏项影响后续消息 | 区分解析错误、请求错误和参数错误；合法批次返回响应数组，通知不产生响应 |
| 模型使用 `Class Member` 得到空结果，转而索取整类成员 | 索引中存在该类时按限定成员查询，披露 `query_interpretation` |
| 错误成员名使模型反复搜索相似概念 | 对精确成员筛选的空结果返回词法相近的名称；不把近似名称解析为别名 |
| 示例列表携带过长的关联符号数组 | 每个示例预览最多 20 个符号，并标记总数和截断 |
| 提示返回 JSON 仍有围栏、额外段落 | 测试提供 `--json-mode`，同时记录解析状态与结束原因；不接受截断输出 |
| 模型停在索引、反复扩大查询或引用过多页面 | 提供调用端精简系统提示：读目标重载、区分声明与继承、证据充分即停止、引用至多三个必要 URI |

MCP 版本为 `0.3.1`。精简提示位于 `docs/agent-system-prompt.txt`，完整说明位于 [智能体查询指南](../docs/AGENT_QUERY_GUIDE.md)。提示需由调用端显式加载，不会随 MCP 自动注入，也不包含测试题答案。

### 冻结实现的完整验证

12 类 × 2 表达 × 2 次重复 × 2 模型，共 96 个样本，全部实际发起。

| 模型 | 完整结束 | 目标字段通过 | 严格自动验收 | 两次均通过的题面 | total_tokens |
| --- | ---: | ---: | ---: | ---: | ---: |
| Flash | 48/48 | 44/48 | 43/48（89.6%） | 21/24 | 519,757 |
| Pro | 43/48 | 42/48 | 38/48（79.2%） | 18/24 | 956,077 |
| 合计 | 91/96 | 86/96 | 81/96（84.4%） | 39/48 | 1,475,834 |

开发集严格通过 56/64；首次留出集通过 25/32（78.1%）。48 个“模型 × 题面”条件中，3 个条件的两次通过状态不同。这证明 temperature 0 下仍有重复结果波动；两个同厂商模型不能代表所有通用模型。

15 个未通过样本集中在四类问题：

- 继承 Run：7 个未通过。3 个未取得所需声明字段；4 个字段正确但含未实际读取的额外引用。工具可读到声明，不能把这些失败称为解析器丢失返回类型。
- 示例分页：4 个未通过。3 个输出截断（包括空白输出）；1 个跳过要求的分页请求。不能把已返回总数当作完整流程通过。
- 交运算生命周期：2 个在已经读到所需原文后继续查询，耗尽轮数。
- 坐标建点：2 个未匹配预设类型契约。其中选择另一个真实重载的情况需结合下文题面限制理解。

### 增加查询指引的已知失败题回归

仅复测上述四类：4 类 × 2 表达 × 2 次 × 2 模型，共 32 个样本。使用相同查询实现、题面、JSON 输出和预算上限，新增 `--use-guide`。此时继承题已经看过，原题库中的 `holdout` 标签不再意味着本阶段是盲测。

| 同一组题面 | 完整结束 | 严格自动验收 | 两次均通过的条件 | 工具调用 | total_tokens |
| --- | ---: | ---: | ---: | ---: | ---: |
| 未加指引 | 27/32 | 17/32（53.1%） | 7/16 | 130 | 780,807 |
| 加入指引 | 32/32 | 28/32（87.5%） | 14/16 | 115 | 580,861 |

在这个已知失败子集上，严格通过率增加 34.4 个百分点，工具调用减少 11.5%，token 减少 25.6%。不能把 87.5% 当作改进后全题库成绩，也不能与完整验证的 84.4% 直接相减。没有用指引重跑全部留出题。

仍未通过的 4 个样本，两次重复的失败类型一致：

1. Flash 的继承题有 2 次字段及所需原文正确，但引用了未读取的额外类页，未达到严格引用验收。
2. Pro 的建点题有 2 次选择 `CreatePoint(CATICkeParm_var,CATICkeParm_var,CATICkeParm_var)`，返回 `CATIGSMPointCoord_var`。本机原文确认这是实际重载，不能称为编造 API。冻结题库预设的是 `const double*` 重载，而该表达只写了数值坐标示例、未明确排除参数对象路线。因此本轮保留原计分并披露歧义；下一轮应先明确“已持有 double 数组、不得引入参数对象”的输入约束，不能事后改题提高旧成绩。证据：`caadoc://Doc/generated/refman/GSMInterfaces/interface_CATIGSMFactory_20836.htm#CreatePoint(CATICkeParm_var,CATICkeParm_var,CATICkeParm_var)`。

四个阶段累计 160 个样本，API 报告 2,647,246 个 total_tokens，包含缓存输入，不是计费金额。密钥只用于官方端点请求，没有写入仓库、报告或测试轨迹。
